# 3 天 13 次提交：我和 AI 结对写出一个上架级 iOS App 的全过程

> 这是一份真实的 Vibe Coding 复盘。项目叫「续吗」（ShouldRenew）——在 AI 订阅下次扣款前问你一句：还该不该续。
> 从第一行代码到 App Store 上架清单，全部由人与 AI 结对完成，全程约 3 天，13 次提交，2658 行 Swift，0 行后端。

![hero](story/images/vibe-1-hero.png)

## 一、做了个什么 App

一句话：**到期前问一句，这笔 AI 会员还该不该续。**

- 3 个 Tab：今日（决策卡）、清单、设置
- 26 个主流 AI 套餐目录（ChatGPT/Claude/Cursor/豆包/可灵……），选模板 20 秒录入
- 扣款前 7/3/1 天本地通知，文案是问句不是账单：「Cursor Pro 3 天后扣 $20，续吗？」
- 决策三选一：续 / 先取消（附微信、支付宝、App Store、官网四渠道取消步骤）/ 再想 1 天
- 纯本地：无账号、无网络、无后端，数据只存在手机里

![numbers](story/images/vibe-3-numbers.png)

## 二、过程复盘：三轮迭代

**第一轮（D1 夜）：产品 PRD 交给 AI，收获一个"它以为你要的"MVP。**
最初的 PRD 是写给"人"看的产品文档。AI 跑通了完整骨架——但也自由发挥出了全英文界面、月报海报、汇率换算。都能跑，但不是我要的。

**第二轮（D1 深夜～D2）：真实用户反馈一次打回 4 条。**
图标要设计、清单点进去会空、决策页滑条数字失控、选模板名称不填充。逐条修复的过程中，把状态机、提醒规划、目录这些纯逻辑抽成了独立的 SwiftPM 包，配上 16 个单元测试——之后 UI 怎么改都不怕碰坏核心。

**第三轮（D2～D3）：一份"实现型 PRD"推倒重来。**
新版 PRD 明确写了 MUST / MUST NOT（不要饼图、不要金额大字报、不要月报 Tab）、逐字的文案表、逐项的验收用例。AI 据此整体重写做减法：砍掉月报、砍掉用量统计，只留决策闭环。之后是撤销/恢复路径、目录扩到 26 项、上架合规配置。

## 三、人机分工（这才是 Vibe Coding 的真相）

| 人（产品负责人） | AI（结对工程师） |
|---|---|
| 定方向：写 PRD、砍范围、定视觉色 | 实现：SwiftUI + SwiftPM + 本地通知 |
| 拍板产品细节：「点完续反悔了怎么办」「目录要覆盖主流套餐」 | 质量兜底：16 个单测 + UI 回归测试 |
| 验收：真机截图、手测流程、报告 bug | 排雷：隐私清单、出口合规、权限串清点 |
| 内容与增长：商店文案、上架清单 | 文档：README、清单文件、迁移方案 |

AI 不会主动想到"用户点完续又反悔了怎么办"——这类产品判断全部来自人。
AI 也不会替你承担审核风险——隐私清单、失效购买按钮这些雷，是你要求"上架前过一遍"它才逐个排掉的。

## 四、注意事项（每条都是真金白银的教训）

**1. 给 AI 的 PRD 要"实现型"，不要"产品型"。**
产品文档留下大量解释空间，AI 会用想象力填满（英文 UI、海报、汇率换算都是这么来的）。实现型 PRD 的三件套：MUST NOT 清单、逐字文案表、验收用例。你写得越死，它自由发挥越少。

**2. 重写 ≠ 重构，回归测试要先于重写。**
AI 重写添加页时，把"选中模板自动填充名称/价格"的逻辑悄悄弄丢了——代码能编译、界面能打开，只有真实点击才发现。教训：**让 AI 重写之前，先让 AI 写好回归测试**。这次是用户手测抓到的，下次可能没这么幸运。

**3. 副作用要集中管理。**
"再想 1 天"排好的通知，被紧随其后的"全量重排提醒"删掉了，功能永远不响但代码看起来完全正确。把排程收口到一个入口函数，再用单测锁住规则（7/3/1 天、续后静默、过期跳过），这类 bug 才藏不住。

**4. 人给的规格也可能是错的，敢说不。**
"使用次数上限设成无符号整数最大值"——AI 照做了，滑条拉一下数字直接上天，第二天打回重做。Vibe Coding 不等于无脑执行：对伤害体验的规格要提出替代方案，再由人拍板。

**5. 纯逻辑抽包 + 测试，UI 层才敢随便改。**
模型、目录、取消指南、提醒规划全在 `ShouldRenewCore` 包里，`swift test` 十几秒出结果，不依赖模拟器。三轮大改版（含一次整体重写）没有伤到核心逻辑，靠的就是这层。

**6. 上架是隐藏的大头工作量。**
隐私清单文件（不交就过不了归档校验）、出口合规声明、声明了却没在用的权限串（审核会问）、"内购尚未接入"的失效按钮（2.1 条款直接拒）——这些写代码时没人提，提审前全是必答题。让 AI 按清单逐个排掉，比自己查文档快得多。

**7. 平台行为要有"防御 + 证据"。**
用户报告"清单点进去回来就空了"，无法稳定复现（疑似系统版本 List 行为）。处理方式：移除可疑结构（分段选择器嵌在列表行内）+ 补一条自动化回归。修不了的系统 bug，至少要让它的触发条件消失。

**8. 数据迁移别裸奔。**
两次改数据模型，旧用户的 JSON 都做了逐字段迁移（含枚举值映射、改名目录映射），并且有专门的迁移单测。改动最狠的那次重写，唯一不动的是用户数据。

## 五、工作流速览

- 工具：AI 结对编码 Agent（对话式，直接在仓库里读写文件、跑命令）
- 反馈闭环：模拟器截图 → 人看图提意见 → AI 改 → 重装再截图
- 测试：核心逻辑 `swift test`（十几秒）+ 关键路径 XCUITest（真机流程走查）
- 每个"需求包"一个 commit，PRD/切图/清单全部进仓库，AI 随时可查
